The problem

Between “the numbers don’t match” and a fix — a week of manual work.

Today · Lakebridge reconcile

A list of differences

  • Reports which columns/rows differ — e.g. unit_price differs on 1,844,309 of 2,000,000 rows
  • Stops at the symptom — no mechanism, no source, no proof
  • Engineer opens the ETL, hypothesizes, writes queries — days per table
With ReconResolve

The mechanism, the culprit, the proof

  • Category + exact migrated derivation + ⚠️ likely-culprit sub-expression
  • The 📄 source script (path + line) + a runnable confirming query + a fix
  • UC lineage trace-back + confidence — a reviewer-ready notebook in minutes

How it works

Two tiers — every verdict backed by a query, never a bare model guess.

The deterministic tier concludes and confirms with a query; the agentic tier is entered only for the residual, and a model cause is promoted only if its confirming query matches.

Tier 1 · Deterministic

Rule-based, query-confirmed — the default

  • Per-dialect probes classify the mechanism
  • Parses the migrated SQL → transformation logic + culprit + script location
  • One confirming query per finding sets verdict + confidence
  • Threshold-aware · schema & aggregate RCA · UC lineage · fixes
Runs anywhere — no Genie, no model, no external calls.
Tier 2 · Agentic

Foundation-model, query-gated — optional

  • Reconstructs the migrated derivation from source columns
  • Proposes the precise cause and a confirming query
  • Promoted only if the query matches every row — else needs-review
  • Interactive (Genie Code) or headless (FM endpoint) — same gate
Guardrail: the query is the gate. A wrong hypothesis doesn’t stick.

Decision guide

Genie Code isn’t enabled everywhere. It never blocks ReconResolve: deterministic runs anywhere; agentic runs wherever a Foundation-Model endpoint is permitted.

✅ What worked

  • Explains every mismatch and proves it with a live query
  • Shows the migrated derivation, the ⚠️ culprit sub-expression, and the 📄 script path + line
  • Deterministic (rules) and hybrid (query-gated FM) — same engine, one flag
  • Per-finding confidence + a run-level rollup; UC lineage trace-back + blast radius
  • Identical output on App, CLI & Skill; 6 concurrent runs held

🔎 Watch-outs

  • Agentic root-cause needs an FM endpoint + a good confirming query — query-gated, so a miss stays needs-review, never wrong
  • TB-scale needs wider / higher-cardinality rows (50M / 8.5 GB shown; TB = data-gen + warehouse cost)
  • A joined derivation (e.g. FX) needs the lookup table’s columns — supplied via join-context
