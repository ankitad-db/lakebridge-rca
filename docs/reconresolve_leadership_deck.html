ReconResolve

Post-Lakebridge reconciliation · root-cause analysis

Reconcile tells you what differs. ReconResolve tells you why — and proves it.

A migration reconcile flags thousands of mismatched rows and columns. ReconResolve reads the migrated SQL, pinpoints the exact transform and the part that broke, and confirms every verdict with a live query — deterministically by default, with an agentic layer for the hard long tail.

The gap

Between "the numbers don't match" and a fix, there's a week of manual detective work.

Today · Lakebridge reconcile

A list of differences

Reconcile compares source vs. target and reports which columns and rows differ — e.g. unit_price differs on 1,844,309 of 2,000,000 rows. Correct, essential — but it stops at the symptom. A migration engineer still has to open the ETL, read the transform, form a hypothesis, and write queries to prove it. Across a star schema that's days per table.

With ReconResolve

The mechanism, the culprit, the proof

For every difference: the category (precision, timezone, boolean, formula…), the exact migrated derivation, the ⚠️ likely culprit sub-expression, the source script it came from, a runnable confirming query, and a suggested fix — as a reviewer-ready notebook, in minutes.

How it works

Two tiers. Every verdict is backed by a query — never a bare model guess.

The deterministic tier concludes the known mechanisms and confirms each with a live query. The agentic tier is entered only for the residual long tail, and a model-proposed cause is promoted only if its confirming query matches.

Tier 1 · Deterministic

Rule-based, query-confirmed

No LLM. Reproducible and auditable — the default.

  • ${CHECK} Per-dialect probes classify the mechanism
  • ${CHECK} Parses the migrated SQL → the transformation logic + the culprit sub-expression
  • ${CHECK} One confirming query per finding; verdict + confidence set from the result
  • ${CHECK} Threshold-aware (within-tolerance ⇒ benign), schema & aggregate RCA, suggested fixes
Runs anywhere — no Genie, no model, no external calls. The whole verdict is a rule plus a query you can re-run.
Tier 2 · Agentic

Foundation-model, query-gated

Only the residual the rules can't name. Optional.

  • ${SPARK} Reconstructs the migrated derivation from the source columns
  • ${SPARK} Proposes the precise cause and a confirming SQL query
  • ${SPARK} Promoted only if the query matches every row — else it stays needs-review
  • ${SPARK} Interactive (Genie Code) or headless (FM serving endpoint) — same gate
Guardrail: the model widens coverage and writes the narrative; the query is the gate. A wrong hypothesis simply doesn't stick.

Proof · live demo

Retail "Sales & Revenue" mart — Snowflake → Databricks, 2M rows, genuine Lakebridge reconcile.

Two beds share the same rich composed ETL. The deterministic bed resolves 13 findings at 98%, every verdict query-confirmed. The hybrid bed adds three defects no rule can name — each precisely root-caused by the agentic tier and proven by a live reconstruction query:

Agentic · confirmed fact_sales.net_revenue 
ROUND(qty*price*(1+tax)
   - qty*price*discount, 4)

Missing cross-term. Discount & tax applied additively — the (1−d)(1+t) cross-term +d·t is dropped, inflating revenue.

${CHECKC} query-confirmed · 95%

Agentic · confirmed fact_sales.amount_usd 
ROUND(qty*price*fx.rate, 2)
JOIN dim_fx
  ON fx_date = trunc(dt,'MM')

FX join grain. Joined at month-start instead of the daily rate — intra-month drift is lost.

${CHECKC} query-confirmed · 95%

Agentic · confirmed fact_sales.status_bucket 
CASE status_code
  WHEN 'A'..'C'..'P'
  ELSE 'Unknown' END

Dropped CASE branch. No arm for 'R' (Returned) — those rows collapse to 'Unknown'.

${CHECKC} query-confirmed · 95%
