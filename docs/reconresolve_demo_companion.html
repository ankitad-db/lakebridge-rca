Speaker notes

~90-second script

Open
"When a Lakebridge migration reconciles and the numbers don't match, someone spends days hand-tracing which transform broke. ReconResolve turns that into minutes — and every answer is backed by a query, not a guess."
The how
"It reads the reconcile metadata plus the migrated SQL, and root-causes each difference two ways: a deterministic tier — rules + one confirming query, no LLM — and a hybrid tier that adds a query-gated FM fallback for the hard, hand-tweaked transforms."
Deterministic
"Here's a pure-deterministic run — banner says Deterministic. Thirteen findings: precision, case, boolean, timezone, dropped rows — each with the transform logic, the script location + line, the likely culprit, a confidence, and lineage. Fully auditable, reproducible, no model in the loop."
Hybrid
"Same engine, hybrid mode. The rules nail the mechanical defects. The agentic tier earns its keep on the composed transforms — a missing formula term, a wrong join grain — where it reconstructs the target column and promotes only when a live query confirms. If it can't confirm, it stays needs-review — it never fakes a verdict."
Trust
"That's the whole design point: the query is the gate. The model proposes; the system disposes. Worst case degrades to needs-review, never a wrong answer presented as fact."
Scale
"It survives prod volume — 50M rows / ~17 GB, RCA in ~90 seconds, because it works on the bounded recon sample, not the raw data."
Close
"Three surfaces — App, CLI, Genie skill — same engine, same notebook. Pick the surface your workspace policy allows; pick deterministic or hybrid per run with one flag."

Honesty guardrail if asked "how good is the AI part?": it adds verdict-level precision on composed transforms rules can't name; it's query-gated, so unconfirmed cases fall back to needs-review. Don't claim a fixed hit-rate — claim the gate.

The demo data

What the recon ETL actually is

A realistic retail "Sales & Revenue" mart, migrated Snowflake EDW → Databricks Unity Catalog, seeded with one defect per RCA mechanism so the demo exercises every feature.

Shape

  • Star schema: fact_sales + dim_customer, dim_product, dim_fx (daily rates)
  • Landed raw extract → rebuilt gold tables via an as-built target SQL (*_target.sql)
  • That SQL is dual-purpose: it builds the target and is the artifact the RCA parses for transform logic + agentic hypotheses
  • Volumes: 2M fact rows (demo) · 50M / ~17 GB (prod-volume proof)

Two beds, one flag

  • Deterministic det_target.sql — defects rules fully catch
  • Hybrid hybrid_target.sql — adds composed-transform defects that need the agentic tier
  • Reconciled with real Lakebridge reconcile → each bed gets a recon_id
  • Stress: many concurrent recon jobs; XL bed for the 50M-row run

Seeded defects (the demo's ground truth)

  • Det unit_price — ROUND(…,2) scale loss
  • Det customer_name — UPPER(TRIM()) case/format
  • Det order_ts_utc — + 5h timezone shift
  • Det is_active — 'Y'/'N' → boolean mapping
  • Det dropped rows — a load filter (order_id % 500)
  • Hybrid net_revenue — discount & tax applied additively; the (1−d)(1+t) cross-term is missing
  • Hybrid amount_usd — FX joined at month-start grain, not the daily rate
  • Hybrid status_bucket — the 'R' (Returned) CASE branch was dropped
  • Benign tax_rate — within tolerance → correctly not flagged

What to point at

Features to highlight

Genie Code skill

  • One prompt in. "Root-cause reconciliation <recon_id>" — no config to hand-write
  • Mode banner up top — Deterministic vs Hybrid, so the run's mode is unambiguous
  • Deterministic = Genie is just the trigger — llm_synthesis: false, no LLM in the RCA
  • Hybrid = interactive agentic tier — proposes a cause + reconstruction query, promotes only if it confirms
  • Self-contained notebooks — per table + an index, with transform logic, script location, culprit, confidence, lineage
  • Best for flexible workspaces — the richest, most interactive surface

Databricks App

  • Zero local setup — web UI for analysts & leadership
  • RCA MODE selector on every page — Deterministic ↔ Hybrid (det + agentic fallback)
  • Confidence per finding + a run-level rollup across the whole recon
  • Trigger a reconciliation from the UI (auto keys → auto-fix → RCA), or analyze an existing recon_id
  • Same notebook output as CLI/Skill — one engine behind all three
  • Best for Genie-restricted orgs — governed, no-terminal access

True on every surface (App · CLI · Skill)

  • Two tiers, one flag — deterministic (auditable, no LLM) or hybrid (query-gated FM fallback)
  • Code-aware RCA — 🔧 transform logic · 📄 script path + line · ⚠️ likely culprit
  • Confidence + provenance on each finding; UC lineage trace-back to where the defect entered
  • The query is the gate — nothing is presented as proven unless a live query confirms it
  • Suggested, review-then-run fixes — never auto-applied
